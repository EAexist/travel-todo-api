# Validation Plan - 0001-task-event-architecture

## Baseline

ADR-0001 작업 이벤트 구조 적용 이전 기존 코드

## Target

ADR-0001 작업 이벤트 구조 적용 이후 코드

## Goals

* **동일한 부하에서의 Business Operation E2E P95 지연 시간**
  - 예상 결론: 부하 조건 ~ requests/s 에서는 [Baseline/Target]의 E2E P95가 [Amount] 더 낮거나 같고 부하 조건 ~ requests/s 에서는 [Baseline/Target]의 E2E P95가 [Amount] 더 낮거나 같다.
  
  - Grafana Query:
    ```promql
    histogram_quantile(
      0.95,
      sum(
        rate(reservation_analysis_e2e_duration_seconds_bucket[1m])
      ) by (le)
    )
    ```


* **지속 가능한 Business Operation 최대 처리량**
  - 예상 결론: ~리소스의 Worker를 Target 구조에 추가했을 때 [Baseline/Target]의 지속 가능한 Business Operation 최대 처리량이 [Amount] 더 높다.
  - 
  - Grafana Query:
    - Baseline:
      ```promql
      sum(rate(http_server_requests_seconds_count{method="POST", uri="/trip/{tripId}/reservation/analysis/text"}[1m]))
      ```
    - Target:
      ```promql
      rate(reservation_analysis_worker_completed_total[1m])
      ```
  - 기타:
    - Offered Load 증가에 따라 Business Operation Throughput이 함께 증가하는 구간을 확인합니다.
    - Offered Load가 증가해도 Throughput이 더 이상 증가하지 않는 시점을 saturation point로 판단합니다. 단, E2E P95 및 Error Rate가 목표치를 초과한 구간은 제외합니다.
    - Baseline: `http_server_requests_seconds_count` (Spring API 처리 완료 기준)
    - Target: `reservation_analysis_worker_completed_total` (Worker의 Business Operation 완료 기준)


* **동일한 처리량에서의 CPU 및 Memory 사용량**
  - 예상 결론: 동일한 처리량을 달성할 때 [Baseline/Target]의 Spring 및 DB의 CPU/Memory 사용량이 [Amount] 더 효율적이며, trade-off 로 Worker가 [Amount] 의 CPU/Memory 사용량을 요구해 인프라 가격을 대입할 경우 [Baseline/Target]이 더 비용 효율적이다.
  
  - Grafana Query:
    - CPU
      ```promql
      process_cpu_usage * 100
      ```
    
    - Memory
      ```promql
      jvm_memory_used_bytes{area="heap"}
      ```

* **Error Rate**
- Grafana Query:
  - Baseline:
    ```promql
    rate(http_server_requests_seconds_count{status=~"5..", method="POST", uri="/trip/{tripId}/reservation/analysis/text"}[1m])
    ```
  - Target:
    ```promql
    sum(rate(http_server_requests_seconds_count{status=~"5..", method="POST", uri="/trip/{tripId}/reservation/analysis/text"}[1m])) 
    + 
    sum(rate(reservation_analysis_worker_unhandled_error_total[1m]))
    ```

## Metrics

### k6

* **Offered Load**
  - Metric: k6 request rate

### API

* **Business Operation E2E 처리 지연 시간**
  - Metric: `reservation_analysis_e2e_duration_seconds_bucket` (Custom)
  - API 요청 수신부터 DB 영속화 완료까지의 E2E 지연 시간

* **Business Operation Throughput (Baseline)**
  - Metric: `http_server_requests_seconds_count` (Native)

* **Spring API CPU Usage**
  - Metric: `process_cpu_usage` (Native)

* **Spring API Memory Usage**
  - Metric: `jvm_memory_used_bytes` (Native)

* **Error Rate**
  - Metric: `http_server_requests_seconds_count`

### Worker

* **Business Operation E2E 처리 지연 시간**
  - Metric: `reservation_analysis_e2e_duration_seconds_bucket` (Custom)
  - API 요청 수신부터 DB 영속화 완료까지의 E2E 지연 시간
  
* **Business Operation Throughput (Target)**
  - Metric: `reservation_analysis_worker_completed_total` (Custom)

* **Go Worker CPU Usage**
  - Metric: `process_cpu_seconds_total` (Native)

* **Go Worker Memory Usage** 
  - Metric: `process_resident_memory_bytes` (Native)

* **Unhandled Worker Error Rate**
  - Metric: `reservation_analysis_worker_unhandled_error_total` (Custom)
  - Count of fatal, unrecoverable failures during worker processing.
