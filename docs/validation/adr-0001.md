# Validation Plan - 0001-task-event-architecture

## Baseline

ADR-0001 작업 이벤트 구조 적용 이전 기존 코드

## Target

ADR-0001 작업 이벤트 구조 적용 이후 코드

## Goals

* **동일한 부하에서의 예약 분석 기능 E2E P95 지연 시간**
    - 예상 결론: 예약 분석 기능에 대해 부하 조건 ~ requests/s 에서는 [Baseline/Target]의 E2E P95가 [Amount] 더 낮거나 같고 부하 조건 ~ requests/s 에서는 [Baseline/Target]의 E2E P95가 [Amount] 더 낮거나 같다.
  

* **예약 분석 기능의 지속 가능한 최대 처리량**
    - 예상 결론: ~리소스의 Worker를 Target 구조에 추가했을 때 예약 분석 기능에 대해 [Baseline/Target]의 지속 가능한 최대 처리량이 [Amount] 더 높다.
    - 요청 부하 증가에 따라 처리량이 증가하는 구간을 확인하고, 부하가 증가해도 처리량이 더 이상 증가하지 않는 시점을 saturation point로 판단합니다. 단, Business Operation E2E P95 지연 시간 또는 Error Rate가 목표치를 초과한 구간은 제외합니다.
    - Baseline metric: `http_server_requests_seconds_count` (API 서버 응답 기준)
    - Target metric: `reservation_analysis_worker_completed_total` (Worker의 태스크 완료 기준)


* **동일한 처리량에서의 CPU 및 Memory 사용량**
    - 예상 결론: 동일한 처리량을 달성할 때 [Baseline/Target]의 Spring 및 DB의 CPU/Memory 사용량이 [Amount] 더 효율적이며, trade-off 로 Worker가 [Amount] 의 CPU/Memory 사용량을 요구해 인프라 가격을 대입할 경우 [Baseline/Target]이 더 비용 효율적이다.

Baseline과 Target에 동일한 조건의 부하 테스트를 진행합니다.

* **Probe Test**
    - Smoke testing: load test 모듈 코드와 설정을 검증합니다.

    https://grafana.com/docs/k6/latest/testing-guides/test-types/smoke-testing/
    ```javascript
    export const options = {
    vus: 3, // Key for Smoke test. Keep it at 2, 3, max 5 VUs
    duration: '1m', // This can be shorter or just a few iterations
    };

    export default () => {
    const urlRes = http.get('https://quickpizza.grafana.com');
    check(urlRes, { 'status returned 200': (r) => r.status == 200 })
    sleep(1);
    // MORE STEPS
    // Here you can have more steps or complex script
    // Step1
    // Step2
    // etc.
    };
    ```

    - Breakpoint testing: 본 테스트의 stage 설정값을 결정하기 위해 늘어나는 부하에 대한 서버 반응과 지속 가능한 최대 처리량을 확인합니다.

    https://grafana.com/docs/k6/latest/testing-guides/test-types/breakpoint-testing/

    ```javascript
    export const options = {
    // Key configurations for breakpoint in this section
    executor: 'ramping-arrival-rate', //Assure load increase if the system slows
    maxVUs: 500,
        // Use exponential stages to probe the capacity
        stages: [
            { duration: '2m', target: 100 },
            { duration: '2m', target: 250 },
            { duration: '2m', target: 500 },
        ],  
        // https://grafana.com/docs/k6/latest/using-k6/thresholds/#thresholds-example-for-http-errors-and-response-duration
        thresholds: {
        http_req_failed: ['rate<0.2'], // http errors should be less than 20%
        http_req_duration: ['p(95)<30000'], // 95% of requests should be below 30s
    },
    };
    ```

## Metrics

### k6

* **Offered Load**
  - Metric: `k6_vus`

### API

* **Business Operation E2E 처리 지연 시간**
  - Metric: `reservation_analysis_e2e_duration_seconds_bucket` (Custom)
  - API 요청 수신부터 DB 영속화 완료까지의 E2E 지연 시간

* **Business Operation Throughput (Baseline)**
  - Metric: `http_server_requests_seconds_count`

* **Spring API CPU Usage**
  - Metric: `process_cpu_usage`

* **Spring API Memory Usage**
  - Metric: `jvm_memory_used_bytes`

* **Error Rate**
  - Metric: `http_server_requests_seconds_count`

### Worker

* **Business Operation E2E 처리 지연 시간**
  - Metric: `reservation_analysis_e2e_duration_seconds_bucket` (Custom)
  - API 요청 수신부터 DB 영속화 완료까지의 E2E 지연 시간
  
* **Business Operation Throughput (Target)**
  - Metric: `reservation_analysis_worker_completed_total` (Custom)

* **Go Worker CPU Usage**
  - Metric: `process_cpu_seconds_total`

* **Go Worker Memory Usage** 
  - Metric: `process_resident_memory_bytes`

* **Unhandled Worker Error Rate**
  - Metric: `reservation_analysis_worker_unhandled_error_total` (Custom)
  - Count of fatal, unrecoverable failures during worker processing.
